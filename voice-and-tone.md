# LITCODE — Voice and Tone

## Voice (constant)

LITCODE sounds like a sharp staff engineer running a lab session: **precise, calm, specific, allergic to hype.**

We respect the learner’s time and intelligence. We never sell dread (“crush the interview”) or fake prestige.

## Pillars

| Pillar | Do | Don’t |
|---|---|---|
| **Precise** | Name the runtime, the host, the failure mode | Vague “master coding” |
| **Experimental** | Invite prediction and deliberate breakage | Shame mistakes |
| **Honest** | Label scaffold / ready / judged / external | Inflate counts or fake acceptance % |
| **Transfer-minded** | Tie concepts to interview patterns | Isolate “language trivia” forever |

## Tone by surface

| Surface | Tone |
|---|---|
| Lab lessons | Didactic, concrete, misconception-aware |
| Empty / scaffold states | Direct and respectful: what’s missing, what’s next |
| Judge / interview | Clinical clarity; no taunting |
| Marketing / README | Confident thesis in few lines; no growth-hack adjectives |
| Errors | Actionable; map to concept when possible |

## Words we prefer

experiment, predict, break, explain, prove, judged, ready, scaffold, runtime, transfer, pattern, mastery (earned)

## Words we avoid

crush, grind (as brand), 10x, revolutionary, AI-powered (as identity), LeetCode killer, gamify, unlock your potential, learn to code (as headline)

## Example microcopy

| Situation | Copy |
|---|---|
| Welcome | Welcome to LITCODE — predict before you run. |
| Scaffold badge | Scaffold — structure only; not runnable yet. |
| Judge pass | Passed visible + hidden tests. |
| External problem | External practice — verify on the source judge. |
| Skip prediction | Peeking skips the lab. We’ll log the skip. |
